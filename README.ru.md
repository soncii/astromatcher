# Astro Matcher

Бесплатный mobile-first продукт для астрологической совместимости с Go backend, приватным dashboard аналитики и готовым деплоем на Render.

## Что есть

- Дизайн: английский язык (ориентация на США), responsive, PWA, собственные иллюстрации, без frontend-зависимостей.
- Два шага ввода: имя и дата рождения каждого человека. Сервер рассчитывает солнечные знаки.
- Результат: анимированная оценка «cosmic vibe», описания взаимодействия, три сравнительные шкалы и рекомендации для обсуждения.
- Сохранение отчётов в браузере и кнопка поделиться ссылкой. **Ссылка передаёт только два знака зодиака, не имена/даты рождения.**
- Мониторинг: просмотры, приблизительное количество уникальных сессий, завершённые расчёты, сохранения, репосты, источники (TikTok, Shorts, Instagram, Google и UTM), страны, динамика по дням UTC, CSV экспорт.
- Хранилище аналитики: локально JSONL, на бесплатном хостинге Supabase Postgres через REST. Ключ Supabase остаётся на сервере.
- Геолокация: Cloudflare `CF-IPCountry` или резервный сервис `country.is` по IP. Если нет данных, честно показывает Unknown.
- Без платёжных функций, регистрации, трекеров рекламы и платного AI API.

**Важно:** это демо-движок по приблизительным датам Солнца, а не научный анализ и не полноценная синастрия по натальным картам. Баллы условные, детерминированные и предназначены для развлечения. Точные периоды смены знаков зависят от года и времени.

## Запуск локально

Требуется Go 1.23+.

```bash
cp .env.example .env
# Измени ADMIN_PASSWORD и ANALYTICS_SECRET в файле .env
go run .
```

Открой `http://localhost:8080`. Админка: `http://localhost:8080/admin`. Пароль берётся из `ADMIN_PASSWORD`. Без него статистика недоступна, но публичное приложение работает.

```bash
go test ./...
go vet ./...
```

### Docker (самостоятельный хостинг)

```bash
docker build -t astromatcher .
docker run -d --name astromatcher -p 8080:10000 \
  -e ADMIN_PASSWORD='strong-different-password' \
  -e ANALYTICS_SECRET='random-32-plus-character-secret' \
  -v astromatcher-data:/app/data astromatcher
```

В режиме Docker с volume локальные JSONL-события сохраняются. Для внешнего размещения использовать HTTPS reverse proxy.

## Бесплатный хостинг: Render + Supabase

**Почему два сервиса:** Render Free может уйти в сон после 15 минут простоя и теряет файлы при рестарте/редеплое. Для постоянного хранения аналитики нужен внешний сервис. Supabase Free предоставляет 500 MB PostgreSQL и REST API. Проект с низкой активностью может быть приостановлен после недели.

1. Создай новый проект на https://supabase.com/ (Free).
2. Открой Supabase **SQL Editor** и выполни содержимое файла [`docs/supabase.sql`](docs/supabase.sql).
3. Из **Project Settings → API Keys** получи **secret key** вида `sb_secret_...` (НЕ публикуемый `sb_publishable_...`). Из настроек проекта скопируй Project URL вида `https://xyz.supabase.co`.
4. Загрузи папку проекта в GitHub (убедись, что `.env` не загружен).
5. На https://dashboard.render.com/ выбери **New → Web Service**, подключи GitHub репозиторий, выбери **Docker**, тариф **Free**. Можно использовать `render.yaml` (Blueprint).
6. В Environment добавь:
   - `ADMIN_PASSWORD`: сильный уникальный пароль.
   - `ANALYTICS_SECRET`: случайные 32+ символов (одинаковый между рестартами).
   - `SUPABASE_URL`: URL проекта Supabase.
   - `SUPABASE_SECRET_KEY`: **секретный** серверный ключ.
   - `TRUST_PROXY_GEO=1` для реального IP посетителя за прокси Render.
   - `COUNTRY_LOOKUP=on` для определения страны без Cloudflare.
7. После деплоя открой `https://<your-service>.onrender.com`, а для статистики `https://<your-service>.onrender.com/admin`.

**Не используй Render Free Postgres для постоянной статистики:** бесплатная БД Render имеет срок действия 30 дней.

### Cloudflare и собственный домен (необязательно)

Если появится домен, подключи бесплатный Cloudflare, включи **Network → IP Geolocation** и проксирование сайта через Cloudflare (оранжевое облако). Приложение автоматически прочитает `CF-IPCountry`. Если заголовка нет, будет использован `country.is` (бесплатное внешнее API, коммерческое использование разрешено, возможны лимиты/недоступность). IP не сохраняется в базе Astro Matcher, но передаётся провайдеру определения страны при резервном запросе.

## Как отслеживать TikTok / YouTube Shorts

Привязка источников через UTM:

```
https://your-domain.com/?utm_source=tiktok&utm_campaign=astro_scorpio_001
https://your-domain.com/?utm_source=youtube&utm_campaign=astro_aries_002
https://your-domain.com/?utm_source=instagram&utm_campaign=reels_003
```

Первый UTM и referrer сохраняются в `sessionStorage` вкладки и сопровождают все события этой сессии. Статистика в `/admin` показывает источники и страны. Прямые заходы без UTM/referrer помечаются `Direct / unknown`. Встроенные браузеры соцсетей могут не передавать referrer, поэтому UTM надёжнее.

### Ограничения аналитики

- Уникальность **по сессиям браузерных вкладок**, не по физическим людям. Очистка хранения и смена вкладки создают новые сессии.
- Боты без JavaScript не учитываются, часть пользователей отключает аналитику или использует DNT.
- Страна определяется приблизительно по IP, VPN и мобильные сети могут давать погрешность.
- Сводки в админке ограничены последними 30 000 событиями в выбранном периоде. Для большого трафика потребуется серверная SQL-агрегация.
- Локальный JSONL рассчитан на небольшой трафик. При локальном самохостинге регулярно делай резервные копии `data/analytics.jsonl`.
- Публичный endpoint аналитики не защищён от сознательной накрутки посещений. Не используй эти данные для финансовых расчётов.
- IP не хранится. Сервер записывает HMAC-хеш временного идентификатора вкладки, время, источник, тип события, страницу, страну и кампанию. Это не абсолютная анонимность по всем определениям privacy-законодательства.
